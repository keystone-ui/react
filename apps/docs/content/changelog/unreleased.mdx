## Minor changes

### Badge: status tones in solid and soft appearances

Badge has four status tones, `variant="success"`, `variant="warning"`, `variant="info"` and `variant="error"`, and a new `appearance` prop that draws each of them `"solid"` (the default) or `"soft"`, a tinted fill with a border in the tone's colour. The status colours are Tailwind palette steps chosen for Badge, with a pair for light and one for dark; no theme token changes. A status Badge rendered as a link keeps its fill on hover and underlines its text. Other variants ignore `appearance`.

Behavior change for consumers: a Badge with `variant="destructive"` now draws the solid red by default. Use `appearance="soft"` for the tinted look, which now has a border, a slightly deeper red in light mode and a slightly fainter tint in dark mode. Prefer `variant="error"`: `destructive` is deprecated on Badge and will be removed in a later release. The red is now a fixed palette red, like the other three tones, so a Badge no longer follows a customised `--destructive` token; only its focus-ring colour modifiers (`focus-visible:ring-destructive/20`, `dark:focus-visible:ring-destructive/40`) still do. Button's `destructive` variant and the `--destructive` token are unchanged.

### Morphing Tabs: the pill stays within the tabs it moves between

In a `morphing` `TabsList`, the selection pill (and the line variant's bar) could pass the outer edges of the tabs it moved between while a label grew. In the default font, the old pill crossed a participating tab's outer edge by up to about 2px for pill, 8px for rounded and 19px for line. At the end of the list the corresponding maxima were 0px, about 4px and about 15px. On the documented short-label switches the edge paths closely match the previous release. The filled pill keeps its round caps during the glide.

Behavior change for consumers (no prop, export, slot, class or element changes):

- During a glide the pill sets inline `left`, `top`, `width`, `height`, `right: auto` and `bottom: auto`. At rest it removes its geometry and preserves unrelated inline declarations. Update style snapshots or read the bounding box. Motion previously supplied transform, transform origin and shared-layout opacity and pointer-event styles. A `ResizeObserver` on the pill now sees its animated layout size. The controller samples author insets when the switch starts, and its inline geometry takes precedence while moving. Percentage insets and the line's bar height are sampled when the switch starts; a change to them during the switch shows when it ends. Remove positional and size transitions, including `transition-all`, from the pill slot. Color and opacity transitions can remain.
- The pill no longer joins an app's `LayoutGroup` or a parent `motion` element's `layout` animation.
- At rest, inserting, reordering or closing tabs moves the pill with its tab immediately. Removing the active tab as its neighbour becomes active places the pill directly on the neighbour.
- If a participating tab is disconnected or belongs to another list when the controller next checks, the glide ends and the pill returns to its CSS position.
- On each frame the controller can measure a connected list with positive width and height, the pill stays within the outer edges of the tabs taking part in the glide, to within one CSS pixel. These include the tabs involved in earlier selections during the same glide. This holds under positive, axis-aligned ancestor scales. The pill's inset and minimum-size rules must allow it to fit. Changes after the controller's frame pass, rotations, skews, perspective, reflections, transforms between the list and its tabs, and CSS animation or transitions on pill geometry fall outside it. Tabs moved between lists by DOM manipulation, a tab rendered through a portal into a container that another component removes, and glides between tabs more than about 100,000 CSS pixels apart are also outside it.
- `<MotionConfig reducedMotion="always">`, a static `MotionConfig` and the system's reduced-motion setting still make the pill jump.
- Resizing the window during a switch: the pill keeps following the tabs instead of finishing early.
- A rapid selection starts the next glide from the pill's current box, clipped to the span of the tabs after the selection commits. If the boxes no longer overlap, the pill appears on the selected tab. It did not carry velocity before either; the docs no longer say it does.

The registry Tabs item includes the new controller, and the base stylesheet comment explains why the leaving panel is hidden.
