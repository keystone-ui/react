## Minor changes

### Tag gains a `remove` prop that puts the X beside the toggle

New: pass the remove button as `remove`, `<Tag remove={<TagRemove onClick={…} />}>React</Tag>`. Tag then renders a pill `<span data-slot="tag">` holding the toggle `<button data-slot="tag-toggle">` and the remove button side by side, so there is no longer a button inside a button (invalid HTML, which React warns about and which can break hydration). It looks the same as before. Clicking the X does not toggle the tag. When the tag is disabled, its X is disabled too.

On a Tag with `remove`, `className`, `style`, `dir` and `hidden` go to the pill, so layout and hiding classes act on the whole pill, X included. `ref`, `aria-*`, other `data-*` attributes and event handlers go to the toggle button. The pill carries `data-pressed` and `data-disabled`: style its states with `data-pressed:` and `data-disabled:`, because `aria-pressed:`, `disabled:` and `focus-visible:` classes do not match a `span`.

`remove` is typed `Exclude<ReactNode, true>`. `null`, `undefined`, `false` and `""` render a plain Tag, so `remove={canRemove && <TagRemove />}` works (but `0` is given: `remove={count && <TagRemove />}` renders a pill reading "0"); a bare `<Tag remove>` is a type error (and a plain Tag at runtime). Any other value renders the pill, even one that renders nothing. A wrapper that forwards the prop should type it `TagProps["remove"]`, since a `ReactNode` may be `true`. Pass one remove control per Tag: two `TagRemove`s overlap.

What a removable Tag costs compared with the child form:

- `justify-*`, `gap-*` and `cursor-*` classes act on the pill, not on the label row inside the toggle. In a stretched pill the label stays centred; `[&>[data-slot=tag-toggle]]:justify-start` puts it at the start (the X stays at the end).
- `ref` lands on the toggle and `style` on the pill, so a library that measures the ref and moves the styled element (drag and drop, an anchored popup) sees two different elements.
- A custom control that is not a `TagRemove` is not disabled with the Tag: it stays tabbable and clickable.
- A `Tag remove` placed directly in a plain Base UI `ToggleGroup` gets none of the X's key handling: arrows, Home and End pressed on the X act from the group's current item rather than from the X's own Tag, and Shift+Tab goes to the previous tab stop rather than to the X's own toggle. Inside a group, use `TagGroup` with `onRemove`.

Unchanged: a Tag without `remove` renders exactly as before, and `<Tag>React<TagRemove /></Tag>` (the X as a child) still works and still renders the X inside the toggle. Use `remove` in new code.

`TagGroupItem` keeps its API, but with `onRemove` on the `TagGroup` each item now renders as `<span data-slot="tag-group-item">` holding `<button data-slot="tag-toggle">` and `<button data-slot="tag-remove">`. If you select on the old structure, check:

- `[data-slot="tag-group-item"]` is now the pill `span`; the button with `aria-pressed` is its `[data-slot="tag-toggle"]` child, and the label is inside that button.
- `[data-slot="tag-remove"]` is the toggle's next sibling, not its child.
- A `ref` or `data-testid` on the item lands on the toggle button; `className` lands on the pill, so `justify-*`, `gap-*` and `cursor-*` no longer reach the label row (see above).
- The toggle's accessible name is now its label alone ("Alpha", not "Alpha Remove"); the X is a separate button named "Remove". A test that finds the toggle by its old name needs the new one.
- Arrow keys, Home and End pressed on an X move from its own item with the group's orientation, and Shift+Tab goes back to that item, as before. Inside a Base UI `Toolbar` the Toolbar's orientation rules and Home and End do nothing, as before. One difference: in a group with `loopFocus={false}`, an arrow on the first or last X that cannot move now leaves focus on that item's toggle rather than on the X.
- A custom remove control inside a `TagGroup` still uses the child form (`<TagGroupItem>Alpha<TagRemove>…</TagRemove></TagGroupItem>`), which nests a button in a button as before.
- Turning `onRemove` on or off at runtime keeps each item's pressed state and focus, but remounts the label's children.

## Patch changes

### Function `className` now works on every Accordion part and on `CollapsibleContent`.

`Accordion`, `AccordionItem`, `AccordionHeader`, `AccordionTrigger`, `AccordionPanel` and `CollapsibleContent` accept `className` as a function of the part's state (`className={(state) => state.open ? "…" : "…"}`), as their types already declared. Before this, the function was silently dropped and none of its classes reached the element. The function is now called with the Base UI state and its result is merged over the part's own classes, exactly as a string `className` is. A string `className` behaves as before.

---

### Carousel auto-hide arrows keep Button's transitions

With `autoHideArrows`, the previous and next arrows transitioned only `opacity`: the fade's `transition-opacity` replaced Button's own transition list, so the hover colour and press scale snapped. The arrows now fade and keep every transition Button has.

---

### Disabled Checkbox and RadioGroupItem dim outside a Field

A disabled `Checkbox` or `RadioGroupItem` now dims to 50% opacity and shows the not-allowed cursor on its own, not only inside a disabled `Field`. Base UI renders both controls as a `<span>`, which `:disabled` never matches, so the `disabled:` styles did nothing; they now key on Base UI's `data-disabled` attribute as well. Inside a disabled `Field` the control stays at 50%: it does not dim twice.

---

### DropdownMenuSubContent honours its size prop

`<DropdownMenuSubContent size="compact">` now renders 32px items, as `<DropdownMenuContent size="compact">` does. The prop was typed but never reached the popup, so a compact submenu kept 36px rows. A submenu still does not inherit its parent menu's size: pass `size="compact"` to both.

---

### `TagRemove` and the `Toast` close button show a keyboard focus outline again

Both paired `outline-none` with `focus-visible:outline-2`. In Tailwind v4, `outline-none` also sets `--tw-outline-style: none`, and `outline-2` reads that variable, so the focus outline computed to `none`. They now draw the same 2px `ring/50` outline, offset 2px, as `Button`. A mouse click still shows no outline.

---

### Function `className` now works on 91 more parts whose type accepts one.

Base UI lets `className` be a function of the part's state (`className={(state) => state.checked ? "…" : "…"}`). The prop types of 91 parts already declared it, across Button, Checkbox, Switch, RadioGroup, Toggle, ToggleGroup, Tag, TagGroup, Tabs, Slider, Progress, CircularProgress, Avatar, InputOTP, Select, Combobox, DropdownMenu, Popover, Tooltip, Modal, Drawer, AlertDialog, Carousel arrows, CopyButton, CodeBlock's copy button, InputGroupButton and SelectionBar. Before this, those parts silently dropped the function. Now Base UI calls it with the part's state, and the result is merged over the part's own classes exactly as a string `className` is. A string `className` behaves as before.

`ComboboxInput`'s `className` type now accepts only a string. It applies `className` to its `InputGroup` wrapper, which is a plain element, so the function its type used to accept was silently dropped; passing one is now a type error. Props typed with Base UI's wider type (for example `ComboboxPrimitive.Input.Props`) no longer spread into `ComboboxInput` without a type error, even when their `className` is a string; type them as `ComboboxInputProps` instead, or omit or narrow `className`.

`@keystoneui/react/utils` gains `mergeClassName(base, className)`, the helper these parts use. A registry install receives it inlined into each component file that needs it, so `@/lib/utils` still only has to provide `cn`.

---

### Disabled Slider thumb no longer dimmed twice

A disabled `Slider` dimmed its thumb to 50% on top of the 50% already applied to `SliderControl`, so the thumb showed at 25% opacity, fainter than the track and range around it. The thumb now inherits the control's dimming only and matches the rest of the disabled slider at 50%. Cursor, track and range are unchanged.

---

### Long TagGroupItem labels end in an ellipsis

A `TagGroupItem` label too long for its container now ends in an ellipsis, as a `Tag` label does, and the remove button from `onRemove` stays visible inside the pill. Before, the label was cut off with no ellipsis and pushed the remove button out of view. Short labels look the same as before, including a `{" "}` between an icon and the label.

This also fixes `Tag`: an ordinary space on its own between parts, such as `<Icon />{" "}<strong>Label</strong>`, no longer adds a second 4px gap and widens the pill. A non-breaking space is still part of the label.

---

### ToggleGroup: vertical groups move focus with the Up and Down arrows

`<ToggleGroup orientation="vertical">` stacked its items but still moved focus with ArrowLeft and ArrowRight, because `orientation` only set `data-orientation` and never reached the Base UI primitive. It is now passed through, so a vertical group responds to ArrowUp and ArrowDown. Horizontal groups, including their mirrored arrows under `dir="rtl"`, are unchanged.
