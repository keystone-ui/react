## Minor changes

### Upgrade `react-day-picker` 9.14 → 10.0.

**Public API change (minor):** `Calendar` forwards its props straight to `DayPicker`, so the props, slots, and aliases that v10 removes are gone from `Calendar` as well. They are now type errors, and at runtime they do nothing without warning:

| Removed | Use instead |
| --- | --- |
| `fromDate` / `fromMonth` / `fromYear` | `startMonth` (and `disabled={{ before }}` for dates) |
| `toDate` / `toMonth` / `toYear` | `endMonth` (and `disabled={{ after }}` for dates) |
| `initialFocus` | `autoFocus` |
| `onDayKeyUp`, `onDayKeyPress`, `onDayPointerEnter/Leave`, `onDayTouch*`, `onWeekNumberClick` | handle events in a custom `DayButton` / `WeekNumber` |
| `formatters.formatMonthCaption` / `formatYearCaption`, `labels.labelDay` / `labelCaption` | `formatCaption` / `formatYearDropdown`, `labelDayButton` / `labelGrid` |
| `components.Button` | `components.NextMonthButton` / `PreviousMonthButton` |
| `classNames.table` (and other deprecated `UI` keys) | `classNames.month_grid` |

Other notes:

- Persian, Hijri, and other non-Gregorian calendars moved to separate `@daypicker/*` packages, and the `react-day-picker/persian` and similar subpaths are gone.
- `date-fns` 4 and `@date-fns/tz` stay regular dependencies; no peer changes.
- The calendar looks the same as before.

## Patch changes

### `AccordionTrigger` now shows a disabled state: `cursor-not-allowed` and `opacity-50`, applied for both the native `disabled` attribute and Base UI's `data-disabled`. Before this, a disabled trigger looked interactive and kept the pointer cursor.

---

### Upgrade `@base-ui/react` 1.8.0 → 1.9.0. No keystoneui API changes; Base UI added, removed, or renamed no components.

Behaviour changes inherited from upstream:

- `AccordionTrigger` (and Collapsible triggers) now render the native `disabled` attribute instead of `aria-disabled` when disabled (#5607). If you assert `aria-disabled="true"` in tests, switch to `toBeDisabled()`.
- Select / Combobox / Autocomplete: automatic popup unmounting is no longer tied to `actionsRef` (#5734). Call `eventDetails.preventUnmountOnClose()` in `onOpenChange` to keep the popup mounted after close.
- Checkbox, Radio Group and Switch prefer `aria-label` over an associated `<label>` for the accessible name (#5787).
- Scroll Area's viewport no longer has `role="presentation"` (#5813).
- Many fixes for Drawer on iOS (virtual keyboard spacing, swipe velocity on 120 Hz input), Menu/Popover focus-guard loops, and faster mounting for large Select/Combobox lists.

### Upgrade dependencies to latest.

**Runtime deps of `@keystoneui/react`:** `lucide-react` 1.41 → 1.55,
`tailwind-merge` 3.6 → 3.7, `react-resizable-panels` 4.12 → 4.14, `motion` 12.43 → 14.1 (no
public API changes upstream: 13.0 dropped the optional `@emotion/is-prop-valid`
auto-detection, 14.0 removed internal framer-motion compat shims).

**`@keystoneui/mcp`:** `@modelcontextprotocol/sdk` 1.30 → 1.32 (security fix:
the SDK's OAuth client could send credentials to an authorization server chosen
by the MCP server, GHSA fixed in 1.31), `zod` 4.5 → 4.6.

**Tooling / docs:** `next` 16.3 → 16.4 (fixes a critical RCE in `next/og`
`ImageResponse` and an SSRF in image optimization), `@opennextjs/cloudflare`
1.20.10, `wrangler` 4.149, `react` 19.3, Tailwind 4.3.3, `storybook` 10.6.1,
`vite` 8.3, `turbo` 2.11, biome 2.5.15, ultracite 7.12.

**TypeScript 7:** docs, Storybook and the MCP server type-check with TS 7.0
(Next runs it via `experimental.useTypeScriptCli`). `@keystoneui/react` keeps
building its `.d.ts` with TS 6 through the `@typescript/typescript6` bridge,
because tsup needs the TypeScript JS API, which 7.0 doesn't ship. Emitted
declarations are unchanged. The shared config drops
`ignoreDeprecations: "6.0"`, and the docs app drops `baseUrl`.
