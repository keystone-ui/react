## Usage

Import `Toaster` and `toast` from the `toast` subpath.

```tsx
import { Toaster, toast } from "@keystoneui/react/toast";
```

## Composition

`Toaster` is the rendering surface. Mount it once at the root of your app, usually in your root layout. `toast` is an imperative API: call `toast.success(...)`, `toast.error(...)` and the other methods from anywhere in your app to queue a toast for the mounted `Toaster` to render.

This snippet shows where each part goes.

```tsx
// app/layout.tsx
<Toaster />

// anywhere else
toast.success("Saved");
toast.error("Something went wrong");
```

The toast viewport sits above every other layer, including modals and popups. [Popup layering and modality](/docs/concepts/popup-layering) explains the scale.

## API reference

### toast()

`toast()` takes 2 call forms: a message, or an object. A bare message becomes
the **description**: the muted single line, and the default shape of a toast.
Add a `title` for an emphasized line above it.

```tsx
toast("Event has been created.");
toast("Saved", { duration: 10_000 });
toast({
  title: "Event created",
  description: "Sunday, December 3 at 9:00 AM",
  action: { label: "Undo", onClick: undo },
});
```

The same two forms work on `toast.success`, `toast.error`, `toast.warning`,
`toast.info` and `toast.loading`. (Base UI's `toastManager.add({ description })`
maps to `toast({ description })`.)

**Content**: `ToastInput`

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `description` | `ReactNode` | - | The toast message. Filled by a bare `toast("…")` |
| `title` | `ReactNode` | - | Optional emphasized line above the description |

**Behavior**: `ToastOptions`, accepted in either form

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `action` | `ToastAction` | - | Primary action button. Runs `onClick`, then closes the toast |
| `cancel` | `ToastAction` | - | Secondary cancel/dismiss button. Runs `onClick`, then closes the toast |
| `duration` | `number` | Toaster's `duration` | Milliseconds before auto-dismiss. `Infinity` keeps the toast open. Inert on `toast.loading`, which never auto-dismisses; update it by `id` or use `toast.promise` |
| `dismissible` | `boolean` | `true` | Whether the toast can be swiped away or closed. Toasts swipe toward their vertical edge, plus their side for corner positions (`bottom-right` swipes down or right; `top-center` only up) |
| `closeButton` | `boolean` | Toaster's `closeButton` | Show a close button on this specific toast |
| `id` | `string` | - | Pass an existing toast ID to update it in place |
| `onAutoClose` | `() => void` | - | Called when the toast closes on its own: its `duration` ran out, or it was swiped away or closed with Escape. Falls back to `onDismiss` when unset |
| `onDismiss` | `() => void` | - | Called when its close, `cancel` or `action` button or `toast.dismiss()` closes the toast |

Base UI reports no reason for a swipe or Escape close, so Keystone UI treats
them as unattributed: they call `onAutoClose` when it is set and `onDismiss`
otherwise. Each close calls exactly one of the two.

The other methods are:

- `toast.promise(promise, { loading, success, error })`: each state takes the
  same message-or-object input.
- `toast.custom(render, options?)`: renders arbitrary JSX.
- `toast.dismiss(id?)`: closes one toast, or every toast when called without an
  id.

`success`, `error`, `warning` and `info` toasts always get their semantic
color, with no opt-in flag. Only the icon is colored; the title and description
stay neutral.

With no `title`, nothing registers as the toast's accessible name, so Keystone
UI uses the description as an `aria-label` fallback. Passing a `title` labels
it instead.

### Toaster

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `position` | `ToastPosition` | `"bottom-right"` | Where toasts appear on screen |
| `duration` | `number` | `5000` | Default auto-dismiss timeout in ms |
| `limit` | `number` | `3` | Maximum number of visible toasts |
| `closeButton` | `boolean` | `true` | Show a close button on every toast |
| `className` | `string` | - | Additional CSS class for the viewport container |
