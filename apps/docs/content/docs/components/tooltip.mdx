## Usage

Import the parts from the `tooltip` subpath.

```tsx
import { Tooltip, TooltipTrigger, TooltipContent, TooltipProvider } from "@keystoneui/react/tooltip";
```

<Callout type="warn">
**Tooltip is a visual enhancement only.** Base UI's tooltip wires no `aria-describedby` and no `role`. The only `aria-*` attribute anywhere in its tooltip implementation is `aria-hidden` on the arrow, and its trigger is mouse-only. So **no** screen reader announces a Tooltip, and **no** touch device opens one. It is keyboard-reachable, which makes the gap hard to spot.

Never put information in a Tooltip that is not available elsewhere. When the tooltip is the only place some text appears, use the [info tip](#info-tip) pattern below.
</Callout>

## Composition

`TooltipProvider` wraps one or more tooltips, each with a trigger and its content.

```text
TooltipProvider
└── Tooltip
    ├── TooltipTrigger
    └── TooltipContent
```

Tooltips sit above dialogs and popups. [Popup layering and modality](/docs/concepts/popup-layering) explains the scale.

### Info tip

Use this pattern whenever a tooltip carries text that appears nowhere else, such as a metric definition, a units note or an explanation of a threshold.

<ComponentPreview name="tooltip-info-tip" />

It needs all 3 of these parts to work:

1. **The text lives in an always-present `hidden` span**, associated with the trigger through `aria-describedby`. Assistive technology reads that span, not the popup, on every device, open or closed. `aria-describedby` still reads a `hidden` element's text, and `hidden` keeps the span out of reading order, where it would be read a second time. Pointing `aria-describedby` at the popup does not work: it is unmounted while closed, so the reference dangles and assistive technology silently ignores it.
2. **The popup is `aria-hidden`.** Without it the same string sits in the accessibility tree twice while open, and a screen reader in browse mode reads it twice.
3. **`open` is controlled and toggles on click**, so the tip works on touch. Set `closeOnClick={false}`, because `TooltipTrigger` closes on click by default and would otherwise fight the toggle.

On a touch screen, a tap that lands at the end of the label can open the tip too, because browsers snap a tap to the nearest target.

This snippet puts the 3 parts together.

```tsx
const descriptionId = useId();
const [open, setOpen] = useState(false);

<Tooltip open={open} onOpenChange={setOpen}>
  <TooltipTrigger
    closeOnClick={false}
    render={
      <button
        type="button"
        aria-describedby={descriptionId}
        aria-label="Pickup p50 definition"
        onClick={() => setOpen((previous) => !previous)}
      />
    }
  >
    <InfoIcon aria-hidden="true" />
  </TooltipTrigger>
  <TooltipContent aria-hidden="true">{content}</TooltipContent>
</Tooltip>
<span id={descriptionId} hidden>{content}</span>
```

## API reference

### TooltipContent

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `side` | `"top" \| "right" \| "bottom" \| "left"` | `"top"` | Preferred placement side |
| `sideOffset` | `number` | `4` | Offset from the trigger in pixels |
| `className` | `string` | - | Additional CSS classes |
