### Surface Variants

Two surface tiers. `filled` (the default) paints `bg-card`. `outline` has no fill, so the page shows through — use it for chart and table panels, where a filled card on a filled page reads as two stacked surfaces.

Both use a ring rather than a border, deliberately: a ring is a box-shadow with no layout impact, where a border insets the content box by 1px, so flipping a row of cards between variants would shift every child. `outline` rings `border` at full strength where `filled` rings `border-muted` (the same color at half alpha) — with no fill the edge is the only thing defining the card, so it has to do more work.

### Title weight

`CardTitle` is `font-medium`, matching `DrawerTitle`, `AlertDialogTitle`, `AlertTitle`, `EmptyTitle` and `ItemTitle` — every `*Title` part in the library except `ModalTitle`, which is `font-semibold text-lg` because a dialog heading is a different tier.

A dense dashboard panel usually wants more: its heading competes with a table or a chart, where a login card's title competes with nothing. Reach for `className` rather than changing the component, and keep it consistent across the panels on a page — one heavier heading beside a lighter one reads as a mistake:

```tsx
<CardTitle className="font-semibold">Top pages</CardTitle>
```

### Tables in a Card

Put the table in `CardContent`. It then shares the card's horizontal padding with the title, so the heading, the row separators and the cell text all line up:

```tsx
<Card variant="outline">
  <CardHeader>
    <CardTitle>Delivery by squad</CardTitle>
  </CardHeader>
  <CardContent>
    <Table>{/* ... */}</Table>
  </CardContent>
</Card>
```

That is the whole recipe — no spacing tricks. The cell text sits `px-2` further in than the title, which is the table's own column gutter and reads as intentional. Use `size="sm"` for a denser panel.

**Do not zero the spacing for a titled table.** A flush table under a padded `CardHeader` leaves the heading indented three times further than the columns (24px against 8px), and the card keeps its vertical padding below the last row. It looks like a mistake because it is one.

<ComponentPreview name="card-table-flush" />

### A card that is only a table

Zeroing `--card-spacing` is for the case with no title and no description — an explorer table that *is* the card. The header row then sits against the card's edge, and `overflow-hidden` clips the table's square corners to the card radius:

```tsx
<Card variant="outline" className="[--card-spacing:0px]">
  <Table>{/* ... */}</Table>
</Card>
```

Both are in the preview above: padded first, flush second.

## RTL

RTL support in Keystone UI is partial: Base UI handles keyboard navigation and popup positioning when you supply a `DirectionProvider`, but the library's own spacing is written with physical utilities and does not mirror. See [the RTL guide](/docs/rtl) for what works today.

## API Reference

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `size` | `"md" \| "sm" \| "xs"` | `"md"` | The size variant of the card. Resolves `--card-spacing`, which every sub-part reads. |
| `variant` | `"filled" \| "outline"` | `"filled"` | Surface treatment. `outline` drops the fill for panel use. |
| `className` | `string` | - | Additional CSS classes |
