## Usage

```tsx
import {
  Pagination,
  PaginationContent,
  PaginationItem,
  PaginationPrevious,
  PaginationNext,
  PaginationLink,
  PaginationEllipsis,
} from "@keystoneui/react/pagination";
```

```tsx
<Pagination>
  <PaginationContent>
    <PaginationItem>
      <PaginationPrevious href="#" />
    </PaginationItem>
    <PaginationItem>
      <PaginationLink href="#">1</PaginationLink>
    </PaginationItem>
    <PaginationItem>
      <PaginationLink href="#" isActive>
        2
      </PaginationLink>
    </PaginationItem>
    <PaginationItem>
      <PaginationLink href="#">3</PaginationLink>
    </PaginationItem>
    <PaginationItem>
      <PaginationEllipsis />
    </PaginationItem>
    <PaginationItem>
      <PaginationNext href="#" />
    </PaginationItem>
  </PaginationContent>
</Pagination>
```

### Rendered markup

`Pagination` is a list of page *links*. A page control with a URL renders `nav > ul > li > a`. One without a URL, paging by `onClick`, renders `li > button` with `type="button"`. The current page carries `aria-current="page"` on either.

### Pagination or TablePagination

For the footer of a paginated data table, with rows per page, "page N of M" and the four navigation buttons, use [`TablePagination`](/docs/components/table-pagination) instead. A data-table footer is a toolbar with an opaque page index and no per-page URLs.

## Composition

```text
Pagination
└── PaginationContent
    └── PaginationItem
        ├── PaginationLink
        ├── PaginationFirst
        ├── PaginationPrevious
        ├── PaginationNext
        ├── PaginationLast
        └── PaginationEllipsis
```

## API reference

### PaginationLink

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `href` | `string` | - | Page URL. With it the control is an `<a>` (`li > a`); without it, a `<button type="button">` (`li > button`) that pages by `onClick` |
| `isActive` | `boolean` | `false` | Whether this is the current page |
| `className` | `string` | - | Additional CSS classes |
