## Usage

```tsx
import { RollingNumber } from "@keystoneui/react/rolling-number";
```

```tsx
<RollingNumber
  format={{ style: "currency", currency: "EUR" }}
  locale="de-DE"
  value={balance}
/>
```

RollingNumber prints `value` exactly as `Intl.NumberFormat(locale, format)` does and, when `value` changes, rolls only the digits that changed. In animated mode, assistive technology receives one visually hidden formatted value and the moving digits are hidden. With `animated={false}`, the visible text is the accessible value. The roll is a CSS transition timed by `--duration-slow`; it is skipped under `prefers-reduced-motion` and with `animated={false}`. If a digit changes again during its roll, it starts from its previous committed glyph instead of blending, a number that gains or loses a digit changes width at once, and columns keep a fixed width in fonts with tabular figures (for hinted text, see Width and fonts). The default locale is `en-US`. For consistent server and client text, use the same value and formatting options, a locale supported by both runtimes, and compatible Intl locale data. In mixed-direction text, the placement of digit groups, signs, currency and percent symbols can differ from plain text. Copying the number gives the same text as copying the plain formatted number, once (tested in Chromium).

### How it rolls

- Each changed digit moves by exactly one row, whatever the numeric distance: 9 → 0 and 0 → 9 are one step each.
- With `trend="auto"` (the default) digits roll up when the value rose and down when it fell, comparing values, not digits: −5 → −6 rolls down. `trend="up"` or `"down"` fixes the direction. An update with the same formatted text starts no new roll. Any roll already in progress continues.
- Nothing rolls on the first render, on hydration, for a digit that has just appeared, when the options Intl resolves from `format` and `locale` change, in compact or scientific notation, or for `NaN` and `Infinity`.
- Under `prefers-reduced-motion` the new digit is in place on the next frame. Where `@starting-style` is unsupported, digits swap with no motion.

### Formatting inputs

RollingNumber passes `locale` and `format` untouched to `new Intl.NumberFormat(locale, format)` each time React calls it, so the text and any error are Intl's. It compares the options Intl resolved (`resolvedOptions()`) with those of the render before. When they are the same, changed digits roll, even if you pass a new object every render. When they differ, the number snaps to the new text.

`format` and `locale` must be plain data. When the number or its resolved formatting changes, React calls the component again and Intl reads the inputs again. StrictMode adds another call during development. A digit that rolls adds one more call two frames later. An options object or locale whose getters return a different value, or throw, on a later read is not supported. An object edited in place is read again the next time the component renders.

### Width and fonts

- A number that gains or loses a digit, a sign or a separator (999 → 1,000) changes width at once. This is not animated.
- When alignment matters, reserve the width of the widest **formatted string** you expect, for example with `min-w-[8ch]` on the root (it is `inline-block`). `minimumIntegerDigits` only pads the integer part.
- The number never breaks across lines; put a break opportunity outside it if you need one.
- `tabular-nums` is on the root, but it only keeps digits the same width in fonts with tabular figures.
- The root also sets `text-rendering: geometricPrecision`, so digits keep the font's true advance where the system would otherwise round each glyph to whole pixels (hinted text, common on Linux). In our Linux Chromium measurements with Geist, changing only the digits at the same length kept the number's width; a sign, a separator or a change of length still changes it. This turns hinting off for the figure, which shows most at small sizes. To restore the browser's default, pass `className="[text-rendering:auto]"`; where text is hinted, digits can then differ by a pixel or two each.
- For values that change more than about twice a second, pass `animated={false}` or throttle the updates.
- RollingNumber builds a formatter on every update, with or without `animated`; for hundreds of rapidly changing numbers, print plain text from one `Intl.NumberFormat` you keep.

### Accessibility

In animated mode, assistive technology receives one visually hidden formatted value and the moving digits are hidden. With `animated={false}`, the visible text is the accessible value. Live announcements are off by default. Pass `aria-live` and optionally `aria-atomic` on the root to request them.

### Styling hooks

`data-slot="rolling-number"` on the root, `data-slot="rolling-number-digit"` on each digit column (with `data-type` `integer` or `fraction`, `data-place` counted from the decimal point, and `data-direction` (`up` or `down`) on the columns the latest change rolled; it stays after the roll ends, until the next change), and `data-slot="rolling-number-symbol"` on every other part (with its `formatToParts` type in `data-type`, such as `currency`, `group` or `minusSign`). `className` goes on the root.

## RTL

The numeric core displays digits and separators in the numbering system's direction. In a right-to-left paragraph, plain text can place digit groups in a different order around a grouping mark, as with the Swiss German apostrophe. Signs, currency and percent symbols can also appear on a different side.

## API reference

### RollingNumber

Renders a `<span>`. Other span props, including `ref`, events and ARIA attributes, are forwarded to the root. The component owns its children and excludes `dangerouslySetInnerHTML`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `number` | - | Required. Formatted with Intl's own rounding and sign handling, `-0` included (it prints `-0`; `format={{ signDisplay: "negative" }}` prints `0`). `NaN` and `Infinity` print their formatted text and never roll. |
| `format` | `Intl.NumberFormatOptions` | `{}` | RollingNumber passes `locale` and `format` untouched to `new Intl.NumberFormat(locale, format)` each time React calls it, so the text and any error are Intl's. It compares the options Intl resolved (`resolvedOptions()`) with those of the render before. When they are the same, changed digits roll, even if you pass a new object every render. An object edited in place is read again the next time the component renders. |
| `locale` | `Intl.LocalesArgument` | `"en-US"` | Pass your app's locale. For consistent server and client text, use one both runtimes support, with compatible Intl locale data. Must be plain data: see [Formatting inputs](#formatting-inputs). |
| `trend` | `"auto" \| "up" \| "down"` | `"auto"` | `up`: the new digit enters from below. `down`: from above. `auto`: up when the value rose, down when it fell. |
| `animated` | `boolean` | `true` | `false` prints the formatted text directly, with no roll. |
| `className` | `string` | - | Classes for the root, merged with its own. |
