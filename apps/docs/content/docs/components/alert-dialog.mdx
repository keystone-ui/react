## Usage

Import the parts from the `alert-dialog` subpath.

```tsx
import {
  AlertDialog,
  AlertDialogTrigger,
  AlertDialogContent,
  AlertDialogHeader,
  AlertDialogTitle,
  AlertDialogDescription,
  AlertDialogFooter,
  AlertDialogAction,
  AlertDialogCancel,
} from "@keystoneui/react/alert-dialog";
```

## Composition

`AlertDialogContent` holds a header, optional media and a footer with the cancel and confirm actions. Put `AlertDialogCancel` before `AlertDialogAction`, so the primary action comes last.

```text
AlertDialog
├── AlertDialogTrigger
└── AlertDialogContent
    ├── AlertDialogHeader
    │   ├── AlertDialogTitle
    │   └── AlertDialogDescription
    ├── AlertDialogMedia
    └── AlertDialogFooter
        ├── AlertDialogCancel
        └── AlertDialogAction
```

An open AlertDialog leaves the page behind it inert and scroll-locked. [Popup layering and modality](/docs/concepts/popup-layering) explains where it sits among the other layers.

## API reference

### AlertDialog

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `open` | `boolean` | - | Controlled open state |
| `onOpenChange` | `(open: boolean) => void` | - | Callback when open state changes |

### AlertDialogContent

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `size` | `"default" \| "sm"` | `"default"` | Dialog width |
| `overlayClassName` | `string` | - | Classes merged onto the built-in overlay; yours win over the defaults (`bg-black/20` lightens it, `hidden` removes it). Visual only: an alert dialog always leaves the page behind inert and scroll-locked |
| `className` | `string \| ((state: DialogPopupState) => string \| undefined)` | - | Additional CSS classes |

### AlertDialogAction

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `className` | `string` | - | Additional CSS classes |

### AlertDialogCancel

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `className` | `string` | - | Additional CSS classes |
