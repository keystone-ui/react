### Record

`orientation="stacked"` puts the term above the details, and `columns={2}` flows the pairs into two columns that collapse to one below `sm`. This is the shape a read-only detail page wants — the default row layout right-aligns each value against its label, which reads as a summary rather than a record.

## RTL

RTL support in Keystone UI is partial: Base UI handles keyboard navigation and popup positioning when you supply a `DirectionProvider`, but the library's own spacing is written with physical utilities and does not mirror. See [the RTL guide](/docs/rtl) for what works today.

## API Reference

### DescriptionList

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `orientation` | `"row" \| "stacked"` | `"row"` | `row` puts term and details on one line with the value right-aligned; `stacked` puts the term above, left-aligned |
| `columns` | `1 \| 2` | `1` | `2` flows pairs into two columns, collapsing below `sm`. For any other arrangement leave this at `1` and bring your own grid |
| `size` | `"default" \| "sm"` | `"default"` | The size variant |
| `variant` | `"default" \| "card"` | `"default"` | The visual variant |
| `className` | `string` | - | Additional CSS classes |
