---
title: Page Layout
description: The page header and metric grid recipes, and the two utilities that keep them from handing your document a horizontal scrollbar.
---

Keystone ships no layout primitives — no `Grid`, `Stack`, `Flex` or `Container`. Layout belongs in `className`, and a component whose only job is a flex container would be API surface with a versioning cost and nothing else.

What is worth writing down is the handful of utilities that are load-bearing rather than decorative. Each of the ones below fixes a real failure, and each is the thing people delete when tidying up.

## Page header

A title with a description and an action cluster, wrapping safely at every width:

```tsx
<header className="flex flex-wrap items-end justify-between gap-4">
  <div className="min-w-0 flex-1">
    <h1 className="font-semibold text-2xl tracking-tight">Analytics</h1>
    <p className="mt-1 text-muted-foreground text-sm">
      Last 30 days · 128 merged pull requests
    </p>
  </div>
  <div className="flex shrink-0 flex-wrap items-center gap-2">
    <Button variant="outline" size="sm">Export CSV</Button>
    <Button size="sm">New report</Button>
  </div>
</header>
```

Three details do the work:

**`min-w-0 flex-1` on the text column.** A flex item will not shrink below its content's intrinsic width by default, so without `min-w-0` a long title pushes the action cluster off-screen instead of wrapping or truncating. This is the one people leave out.

**`shrink-0 flex-wrap` on the actions.** `shrink-0` stops the buttons being squashed; `flex-wrap` lets a four-button cluster wrap *inside* the header rather than forcing the whole header onto a second line.

**`items-end`, not `items-center`.** With a description present, the action row should align to the bottom of the text column. `items-center` looks fine until you add a description, then reads as misaligned.

Add `truncate` to the `h1` if you would rather clip a long title than wrap it.

### Printing

The header is a plain element, so hide what should not print from your own stylesheet:

```css
@media print {
  header [data-slot="button"] { display: none; }
}
```

## Metric grid

```tsx
<div className="grid gap-4 sm:grid-cols-2 xl:grid-cols-4 [&>*]:min-w-0">
  {/* Card + StatValue + StatDelta per tile */}
</div>
```

**`[&>*]:min-w-0` is not optional.** Grid and flex children resolve their minimum size to `min-content`, so a single long value — an untruncated email, a wide number, a table — pushes its track open and hands the whole document a horizontal scrollbar. It is invisible until real data arrives, and then it affects every page using that grid.

The same applies to a panel row:

```tsx
<div className="grid gap-4 lg:grid-cols-3 [&>*]:min-w-0">
  <Card variant="outline" className="lg:col-span-2">{/* chart */}</Card>
  <Card variant="outline">{/* chart */}</Card>
</div>
```

Gap sizes are a convention rather than a rule — pick one and hold it across a page, since mixed gaps read as a mistake.

## Surfaces

Use [`Card variant="outline"`](/docs/components/card) for chart and table panels. A filled card on a filled page reads as two stacked surfaces; the outline tier lets the page show through, so the panel reads as a division of the page rather than an object sitting on it.

For a table that should run edge to edge, zero the card's spacing:

```tsx
<Card variant="outline" className="[--card-spacing:0px]">
  <Table>{/* ... */}</Table>
</Card>
```

## Sticky regions

Pair every `sticky` with a `z-index` from the scale and, if you have a print stylesheet, with `print:static`:

```tsx
<TableHeader className="sticky top-0 z-[var(--z-sticky)] bg-background print:static">
```

The background is not decorative — a transparent sticky element lets content scroll through it. Use `bg-background` rather than `bg-card` when the region may already sit inside a painted `Card`.

Sticky table headers additionally need a bounded scroll container; see [Table → Sticky Header](/docs/components/table#sticky-header) for why a page-scroll sticky header is not possible.
