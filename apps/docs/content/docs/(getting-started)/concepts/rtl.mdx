Keystone UI has partial right-to-left (RTL) support. This page covers what follows the reading direction and the known component limitations, so you can judge whether the library fits an RTL product before you build on it. [Set up right-to-left layouts](/docs/guides/set-up-right-to-left) has the app setup and the workarounds.

## Summary

Support differs by layer:

| Area | Status |
| --- | --- |
| Base UI keyboard nav and popup positioning | Popups normally inherit direction from the root. Above or below the trigger, `start`/`end` follow the positioner's computed direction. A `DirectionProvider` maps horizontal arrow keys and `inline-*` sides |
| Keystone's own spacing and positioning CSS | 31 of 64 components keep some one-sided gutters, offsets or text alignments on their physical side |
| Explicit `rtl:` handling in the library | Calendar's default month navigation chevrons |
| i18n / locale / message layer | No locale layer; [`StringsProvider`](/docs/components/strings) replaces some built-in English |
| RTL tests or visual baselines | Targeted right-to-left checks for some components; Storybook snapshot comparison of RTL examples such as Reel |

## What works

Components built on [Base UI](https://base-ui.com) inherit its direction-aware behaviour where it applies: horizontal arrow-key navigation, the `inline-start`/`inline-end` popup sides, and slider axis handling. Base UI reads the reading direction for these from its own context, which defaults to `ltr`.

Popup alignment works differently. Above or below the trigger, `start` and `end` use the positioner's computed direction, normally inherited from the root. Beside the trigger, `start` uses the top edge in either reading direction. Alignment offsets and collision handling can move the popup from that edge. Select's item-aligned mode uses the provider's direction. Drawer swipe directions stay physical (`left`, `right`, `up`, `down`), so choose `swipeDirection` for your layout.

That's why an RTL app sets two directions. The root direction (`<html dir="rtl">`) drives popup layout. The provider direction (Base UI's `DirectionProvider`) drives horizontal arrow navigation, including the key that opens a submenu, and logical popup sides. Calendar takes its own `dir` for its day-grid arrow keys.

**A `dir` on a wrapper element is not enough for popups.** A top-level popup (a menu, select, combobox, popover, tooltip, modal or drawer) uses a body portal by default. If only the trigger's wrapper is RTL on an LTR page, that portal still inherits LTR, even with the provider.

## What does not work

**One-sided gutters, offsets and text alignments in 31 of the 64 components keep their physical side in RTL.** They use physical utilities (`pl-`, `pr-`, `ml-`, `mr-`, `left-`, `right-`, `text-left`, `text-right`), which do not respond to `dir`. For example, from `sm` up, the Modal header stays left-aligned and the footer actions align at the inline end.

Calendar uses `rtl:` variants for its default month navigation chevrons. Reel uses logical positioning for its arrows and the scroller's computed direction for paging. Its chevrons and the horizontal fade follow the nearest explicit `dir="ltr"` or `dir="rtl"`. `FileUploadItemName` sets `dir="auto"` so a file name keeps its own direction. RollingNumber's direction and numbering systems are covered in [its RTL section](/docs/components/rolling-number#rtl).

**There is no full i18n layer.** Keystone UI ships no locale plumbing. [`StringsProvider`](/docs/components/strings) replaces some of the library's built-in English; its page lists the text it covers. For package installs, check that your version exports `@keystoneui/react/strings`. `RollingNumber` formats its number with `Intl.NumberFormat` and the `locale` you pass. The default locale is `en-US`. Other components have their own defaults, such as the month formatter in `Calendar` and the byte formatter in `FileUploadItemSize`.

**RTL test coverage is partial.** Unit tests press arrow keys inside a right-to-left `DirectionProvider` for FilterChips, ToggleGroup and TagGroup. Chromium Storybook tests check, among others, Reel paging and the painted fade in both directions, a DropdownMenu submenu's side and keys, and the layout of Tag, Countdown and TablePagination in a right-to-left container. The docs end-to-end tests check Reel's built stylesheet, arrow placement and paging across nested direction settings, and scrollable Tabs in right-to-left. Storybook is configured to compare snapshots of RTL examples such as Reel.
