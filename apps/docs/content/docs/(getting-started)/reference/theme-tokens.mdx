This page is the complete default theme: the CSS the [registry style item](/docs/guides/install-from-the-registry) writes into your `globals.css`, split into its parts. Copy every part, in order, into your main CSS file for a manual setup, and change any value you like. [Theming](/docs/concepts/theming) explains how the parts fit together.

## Imports

The file starts with Tailwind CSS, the library stylesheet and an `@source` directive. Keystone UI components use Tailwind utility classes in their source files, and `@source` tells Tailwind CSS v4 to scan those files so it generates the classes. Without it, component styles are missing.

```css title="globals.css"
@import "tailwindcss";
@import "@keystoneui/react/base.css";

@source "../node_modules/@keystoneui/react/src/**/*.{ts,tsx}";
```

The `@source` path is relative to your CSS file. In a project with a `src/` directory (`src/app/globals.css`), go up two levels: `@source "../../node_modules/@keystoneui/react/src/**/*.{ts,tsx}";`.

## Dark mode variant

The variant makes `dark:` utilities apply inside any `.dark` ancestor:

```css title="globals.css"
@custom-variant dark (&:is(.dark *));
```

[Enable dark mode](/docs/guides/enable-dark-mode#keep-printed-pages-light) shows the screen-only form, which keeps printed pages light.

## Tailwind registration

The `@theme inline` block maps each token to a Tailwind colour, so `--primary` becomes `bg-primary`, `text-primary` and the rest:

```css title="globals.css"
@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-card: var(--card);
  --color-card-foreground: var(--card-foreground);
  --color-popover: var(--popover);
  --color-popover-foreground: var(--popover-foreground);
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);
  --color-secondary: var(--secondary);
  --color-secondary-hover: var(--secondary-hover);
  --color-secondary-foreground: var(--secondary-foreground);
  --color-muted: var(--muted);
  --color-muted-foreground: var(--muted-foreground);
  --color-accent: var(--accent);
  --color-accent-foreground: var(--accent-foreground);
  --color-destructive: var(--destructive);
  --color-destructive-foreground: var(--destructive-foreground);
  --color-border: var(--border);

  --color-input: var(--input);
  --color-input-bg: var(--input-bg);
  --color-ring: var(--ring);
  --color-success: var(--success);
  --color-success-foreground: var(--success-foreground);
  --color-warning: var(--warning);
  --color-warning-foreground: var(--warning-foreground);
  --color-sidebar: var(--sidebar);
  --color-sidebar-foreground: var(--sidebar-foreground);

```

`--info` and `--info-foreground` are not in this block: `base.css` registers them, with the light values as a fallback. Don't copy that registration into your own `@theme inline`. Declare `--info` in both `:root` and `.dark`, or the info `Alert` and `Toast` keep the light-mode blue in dark mode.

## Print values

The style item also writes a `@media print` block that moves the light tokens toward ink: pure black on white, and a `--muted-foreground` dark enough for a laser printer. [Dark mode](/docs/concepts/dark-mode#why-dark-tokens-are-screen-only) explains why print gets light tokens.

```css title="globals.css"
@media print {
  :root {
    --background: #ffffff;
    --foreground: #000000;
    --card: #ffffff;
    --card-foreground: #000000;
    --popover: #ffffff;
    --popover-foreground: #000000;
    --muted: #f4f4f5;
    --muted-foreground: #3f3f46;
    --border: #d4d4d8;
    --border-muted: #e4e4e7;
    --input: #d4d4d8;
  }
}
```

## Base layer

The base layer sets the default border and outline colours, the page colours and a thin scrollbar on code blocks:

```css title="globals.css"
@layer base {
  * {
    @apply border-border outline-ring/50;
  }
  body {
    @apply bg-background text-foreground;
  }

  pre::-webkit-scrollbar {
    width: 5px;
  }
  pre::-webkit-scrollbar-track {
    background: transparent;
  }
  pre::-webkit-scrollbar-thumb {
    background: var(--border);
    border-radius: 5px;
  }
  pre {
    scrollbar-width: thin;
    scrollbar-color: var(--border) transparent;
  }
}
```

<Callout type="warn">
  Keep the `* { @apply border-border outline-ring/50; }` rule in `@layer base`.
  Several components, such as Drawer, Kbd and Table rows, draw a border without
  naming a colour and rely on it. `@keystoneui/react/base.css` does not ship it
  (the default registry style at `/r/default.json` does), so without it those
  borders take the text colour.
</Callout>

## Chart tokens

`--chart-1` to `--chart-5` are 5 categorical slots for chart series, the same hues in every theme. They're separated by lightness rather than hue alone, so they stay distinct under colour-vision deficiency.

## Fonts

Keystone UI reads the base font family from `--font-sans`. Load the font and set the variable in your theme, as [Customize the theme](/docs/guides/customize-the-theme#set-the-font) shows. The [theme builder](/theme-builder) previews these fonts:

| Font | next/font import | CSS variable |
| --- | --- | --- |
| Inter | `Inter` | `--font-inter` |
| Geist | `Geist` | `--font-geist` |
| DM Sans | `DM_Sans` | `--font-dm-sans` |
| Figtree | `Figtree` | `--font-figtree` |
| Public Sans | `Public_Sans` | `--font-public-sans` |
| JetBrains Mono | `JetBrains_Mono` | `--font-jetbrains-mono` |
