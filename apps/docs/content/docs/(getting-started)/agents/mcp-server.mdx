The Keystone UI MCP server lets your AI assistant browse the registry, search for components, read their source and install them into your project when you ask in plain language. This guide connects it to your editor. [How the MCP server works](/docs/agents/how-mcp-works) explains what it does on your machine, and [MCP tools](/docs/agents/mcp-tools) lists what the assistant can call.

## Before you start

You need Node.js with `npx` and one of these clients: Cursor, Claude Code, VS Code, OpenCode or Codex. The server runs with the settings of the project it starts in, so start it only in [projects you trust](#projects-you-do-not-trust).

## Write the config with the init command

Run the init command for your AI client. It writes the MCP config file for your editor:

```bash tab="Cursor"
npx @keystoneui/mcp@latest init --client cursor
```

```bash tab="Claude Code"
npx @keystoneui/mcp@latest init --client claude
```

```bash tab="VS Code"
npx @keystoneui/mcp@latest init --client vscode
```

```bash tab="OpenCode"
npx @keystoneui/mcp@latest init --client opencode
```

```bash tab="Codex"
npx @keystoneui/mcp@latest init --client codex
```

Then restart your editor. In Cursor, also enable the server in **Cursor Settings > MCP Servers**.

## Write the config by hand

To configure the server without the init command, add the config for your editor.

### Cursor

Add the server to `.cursor/mcp.json`:

```json title=".cursor/mcp.json"
{
  "mcpServers": {
    "keystoneui": {
      "command": "npx",
      "args": ["@keystoneui/mcp@latest"]
    }
  }
}
```

Then enable the Keystone UI MCP server in **Cursor Settings**.

### Claude Code

Add the server to `.mcp.json`:

```json title=".mcp.json"
{
  "mcpServers": {
    "keystoneui": {
      "command": "npx",
      "args": ["@keystoneui/mcp@latest"]
    }
  }
}
```

Then restart Claude Code and run `/mcp` to check that the server is connected.

### VS Code

Add the server to `.vscode/mcp.json`:

```json title=".vscode/mcp.json"
{
  "servers": {
    "keystoneui": {
      "command": "npx",
      "args": ["@keystoneui/mcp@latest"]
    }
  }
}
```

Then open `.vscode/mcp.json` and click **Start** next to the keystoneui server.

### Codex

The CLI can't write to `~/.codex/config.toml` for you, so add the configuration by hand:

```toml title="~/.codex/config.toml"
[mcp_servers.keystoneui]
command = "npx"
args = ["@keystoneui/mcp@latest"]
```

Then restart Codex.

## Projects you do not trust

Treat starting the server like running the project's own scripts: do it in projects you trust. Adding a version or a tag to the command does not change this. [How the MCP server works](/docs/agents/how-mcp-works#why-the-project-you-open-matters) explains why.

Before you open a fresh clone, a pull request or a download you have not reviewed:

- If the server is in a configuration that applies to every project (for example `~/.codex/config.toml`), turn it off first.
- Do not approve an MCP server the project configures itself (`.mcp.json`, `.cursor/mcp.json`, `.vscode/mcp.json`, `opencode.json`). A command you recognise still runs with that project's settings.
- To look something up meanwhile, read this site or use [`/llms.txt`](/docs/agents/llms-txt) as reference material. Neither requires starting the local MCP server or running a project command.

If the server has already started in such a project, changing the command afterwards does not undo that.

## Check that it works

Ask your assistant one of these prompts:

```text
Show me all available Keystone UI components
Add the button, card, and input components to my project
Create a sign-in form using Keystone UI components
```

The assistant should answer from the Keystone UI registry, through the `keystoneui` server's tools. If the server doesn't show up or has no tools, see [Troubleshoot the MCP server](/docs/agents/troubleshoot-mcp).
