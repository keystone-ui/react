The `keystoneui-react` agent skill gives your AI assistant the Keystone UI components, patterns and conventions as files it loads when it needs them. It works with Claude Code, Cursor, OpenCode, Codex and Gemini CLI. [Choose an integration](/docs/agents/choose-an-integration) compares it with the MCP server, `AGENTS.md` and llms.txt.

## Installation

Install the skill with the install script:

```bash
curl -fsSL https://keystoneui.io/install | bash -s keystoneui-react
```

Or with the [skills.sh](https://skills.sh/) package manager:

```bash
npx skills add keystone-ui/react@keystoneui-react
```

## Invocation

Your assistant discovers the skill on its own when a task involves Keystone UI, or you can call it with the `/keystoneui-react` command. It covers requests such as:

- building components with Keystone UI
- creating pages from Keystone UI components
- customizing themes and styles
- looking up component documentation

## Contents

The skill is a slim entry point plus topic files, so your assistant pulls the section it needs rather than loading one large guide:

- identity, install, key patterns and the component-selection table in `SKILL.md`
- MCP server setup and tool reference (`mcp.md`)
- CLI and shadcn install paths (`cli.md`)
- theming in depth (`customization.md`)
- topic-specific rules with do and don't code pairs in `rules/`

The files are laid out like this:

```text
skills/keystoneui-react/
├── SKILL.md              # Entry point: identity, install, principles, key patterns
├── mcp.md                # MCP setup + 9 tools reference
├── cli.md                # keystoneui verbs + shadcn add + npm package
├── customization.md      # CSS setup, OKLCH tokens, radius scale, motion/layering
├── registry.md           # Authoring registry items: targets, styles, themes, blocks
├── rules/
│   ├── styling.md        # Semantic colors, layout, hover gating, focus, transitions, z-scale
│   ├── forms.md          # Form, FieldGroup, Field, InputGroup, ToggleGroup, validation
│   ├── composition.md    # render prop, compound parts, group items, Modal title, data-slot
│   ├── data-tables.md    # Filter toolbars, applied state, sorting, pagination, mobile fold
│   ├── icons.md          # lucide-react, no sizing classes, pass as components
│   └── base-vs-radix.md  # render vs asChild, data-attributes, animation patterns
├── agents/
│   └── openai.yml        # OpenAI assistant interface metadata
├── assets/               # Brand icons referenced by agents/openai.yml
└── LICENSE.txt
```

## Evals

`evals/` in the [keystone-ui/react](https://github.com/keystone-ui/react) repository holds one directory per case: a `prompt.md` with a realistic request, and `graders/` asserting what a correct answer must contain. The graders check for subpath imports, `render` rather than `asChild`, `aria-invalid` plus `FieldError` rather than `data-invalid`, and `TablePagination` rather than `Pagination`.

The evals live at the repository root rather than inside the skill, because that's where the plugin evaluator discovers them, and because they're our regression suite, not something a consumer needs shipped to them. Run them from the repository root:

```bash
claude plugin eval . --threshold 0.8
```

The run scores the same prompts twice, with the skill loaded and without it, so the number it reports is whether the skill *helped*, not only whether the model answered well. Use it to catch regressions when components or conventions change.
