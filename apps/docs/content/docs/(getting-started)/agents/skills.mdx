Agent Skills give your AI assistant comprehensive knowledge of Keystone UI components, patterns, and best practices.

## Installation

```bash
curl -fsSL https://keystoneui.io/install | bash -s keystoneui-react
```

Or using the [skills.sh](https://skills.sh/) package manager:

```bash
npx skills add keystone-ui/react@keystoneui-react
```

Supports Claude Code, Cursor, OpenCode, Codex, and Gemini CLI.

## Usage

Skills are automatically discovered by your AI assistant, or call it directly using `/keystoneui-react` command.

Simply ask your AI assistant to:

- Build components using Keystone UI
- Create pages with Keystone UI components
- Customize themes and styles
- Access component documentation

## What's Included

The skill is organized into a slim entry point plus modular topic files. Your AI assistant pulls the section it needs rather than loading one giant guide.

- Identity, install, key patterns, and component-selection table in `SKILL.md`
- MCP server setup and tool reference (`mcp.md`)
- CLI and shadcn install paths (`cli.md`)
- Theming deep-dive (`customization.md`)
- Topic-specific rules with do/don't code pairs in `rules/`

## Structure

```
├── SKILL.md              # Entry point: identity, install, principles, key patterns
├── mcp.md                # MCP setup + 8 tools reference

│   ├── data-tables.md    # Filter toolbars, applied state, sorting, pagination, mobile fold
│   ├── icons.md          # lucide-react, no sizing classes, pass as components

├── evals/                # One directory per eval case (prompt + graders)
├── assets/               # Brand icons referenced by agents/openai.yml

```

## Evals

`evals/` holds one directory per case — a `prompt.md` with a realistic request,
and `graders/` asserting what a correct answer must contain (subpath imports,
`render` rather than `asChild`, `aria-invalid` + `FieldError` rather than
`data-invalid`, `TablePagination` rather than `Pagination`).

Run them with the Claude Code plugin evaluator from the repository root:

```bash
claude plugin eval . --threshold 0.8
```

The run scores the same prompts twice, with the skill loaded and without it, so
the number it reports is whether the skill *helped* — not just whether the model
happened to answer well. Use it to catch regressions when components or
conventions change.
