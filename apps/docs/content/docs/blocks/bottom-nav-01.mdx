## Features

- Real links: a `<nav aria-label>` holding a list of `<a href>`s, each with an icon and a visible text label. The current one carries `aria-current="page"` and gets a filled pill behind its icon, so the current page is not marked by color alone.
- Each link fills one of five equal cells and is at least 44 px tall, so with 200% text on a 320 px screen every link still sits inside the screen and a tap on its edge reaches it, not its neighbor; a label that no longer fits is cut short with an ellipsis and keeps its full accessible name. The keyboard focus outline is drawn inward so the bar's edge cannot clip it.
- Fixed to the bottom of the viewport and layered with the `--z-sticky` token. In print, `md:hidden` still applies to the print layout's width (the paper less its margins): when that width reaches `md` (768 CSS px) the bar is left out, as on a desktop; below it the bar prints once, in normal flow where it sits (`print:static`), not over every page.
- Hidden from `md` up. On a wider screen the same destinations belong in a sidebar: the [sidebar item](/docs/reference/shadcn-sidebar) from `admin-01` is one.
- Takes `items`, `currentHref` and a `label` for the `<nav>` (default `"Main"`). No router dependency: pass the current path from your router, and swap the `<a>` for your router's link component if it renders an `<a>`.
- An item's `icon` is an element (`icon: <Home />`), not the component (`icon: Home`): the installed page is a Server Component and `BottomNav` a Client Component, and an element can cross that boundary while a component function cannot.
- A positive `count` on an item shows a [Badge](/docs/components/badge) over its icon (99+ above 99); `0` or no count shows nothing. The badge itself is hidden from assistive technology; `countLabel` (for example `"3 unread"`) is read after the label instead, so the link is announced as "Inbox (3 unread)".
- Right-to-left: the order mirrors and the badge sits at the inline end of the icon's pill, inside its own link, because only logical properties (`end-0`) are used.

## Scroll padding the bar adds

Below `md`, `BottomNav` renders a scroll-padding rule for the document's scrollport, as a React 19 `<style>` that's hoisted into `<head>` once. It keeps the browser from scrolling a keyboard-focused control to the bottom edge of the screen, under the bar:

```css
@media screen and (width < 48rem) {
  html:where(:has([data-slot="bottom-nav"])) {
    scroll-padding-block-end: calc(var(--bottom-nav-height, 4rem) + env(safe-area-inset-bottom) + 1rem);
  }
}
```

- **Height**: the bar is exactly `--bottom-nav-height` tall (4rem, its top border included) plus the device's bottom safe area. Set the variable on `:root`, where both the bar and this rule read it.
- **Element**: the rule sits on `html`, because that's the element that scrolls.
- **Side**: it sets only the bottom (block-end) side. The top side belongs to your page, for example the offset for a sticky header, and the bar never changes it.
- **Lifetime**: React may leave the `<style>` element in `<head>` after the bar unmounts; its selector only matches while the document holds a bar. An app that keeps left routes mounted but hidden (Next.js `cacheComponents`) still holds the bar while its route is kept alive, so the bottom padding can stay in force on other pages at phone width.
- **Effect**: it never changes the layout. It only acts when the browser scrolls something into view, such as a focused control or an anchor.

The bar doesn't pad your page. [Keep content clear of the bottom nav](/docs/guides/keep-content-clear-of-the-bottom-nav) adds the page padding, moves this rule into your stylesheet under a strict Content-Security-Policy, and combines it with your app's own scroll offsets.

## Surface color

The bar paints `bg-background` with a `border-t`. It's part of the page's own plane, like a sticky table header, not a layer opened over the page: `bg-popover` is for popups, Modal, AlertDialog and Drawer, and in dark mode it would lift the bar a step above the page it belongs to.
